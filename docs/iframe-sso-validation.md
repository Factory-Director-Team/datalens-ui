# Проверки автоматического входа — 2026-10-30

Статус: рабочая ручка подключена как адрес проверки по умолчанию в SSO overlay и Coolify; **Docker-приёмка завершена**. Изолированные браузерные тесты и дополнительный вход через настоящий backend прошли. Настройка развёртывания описана в [инструкции](./iframe-sso.md).

Frontend передаёт bearer в `POST /sso/login`; BFF проверяет разрешение только при входе и выдаёт обычную сессию DataLens. Пользовательский bearer не сохраняется в репозитории или конфигурации. SSO включается явно; нужны точные HTTPS origins и данные общего аккаунта.

## Рабочая ручка

Адрес: `https://dev-ahmad.factorydirector.pro/api/v1/bi/verify`. Проверялись POST с телом `{}` и bearer в Authorization, без переходов по redirects.

| Проверка                 | Результат                                                  |
| ------------------------ | ---------------------------------------------------------- |
| Действующий bearer       | HTTP 200, `{"active":true,"datalens_access":true}`, 0,61 с |
| Без bearer               | HTTP 401, credentials not provided                         |
| Неверный bearer          | HTTP 401, invalid token                                    |
| GET с действующим bearer | HTTP 405, method not allowed                               |

Отдельный Docker-прогон заменил только `SSO_VERIFICATION_URL` тестового BFF на рабочий адрес. В Chromium, Firefox и WebKit вход начинался с пустого профиля браузера, без предварительного посещения DataLens и без подстановки auth cookies. Родительская страница передавала действующий bearer через `openDataLens`.

Все три браузера получили HTTP 204 на `/sso/login`, открыли полный интерфейс в iframe и получили HTTP 200 от профиля. Основная cookie сохранила Secure, HttpOnly, SameSite=Strict и ограничение хостом DataLens. Native refresh и logout вернули HTTP 200; после logout профиль вернул HTTP 401. Отсутствующий bearer дал `401 BEARER_REQUIRED`, неверный — `401 HOST_DENIED`. Общий аккаунт auth и данные в этом прогоне были тестовыми; рабочим был verifier приложения.

## Что выявила приёмка

1. Встроенный nginx образа UI перехватывал OPTIONS и скрывал CORS-заголовок BFF. На публичном порту preflight возвращал HTTP 200 вместо 204; прямой BFF отвечал правильно. Точный `/sso/login` теперь передаётся BFF с его CORS-политикой; прочие URL сохраняют прежнюю обработку.
2. Анонимные Public/Embed загружали дашборд, но преобразование текста обращалось к защищённым Markdown-операциям и получало HTTP 401. Разрешены только две локальные операции `renderMarkdown` и `batchRenderMarkdown` с фиксированными scope `root` и service `mix`. Усиленный тест подтверждает `401` для анонимного `us/getEntry`, успешный рендер без выдачи cookies и видимый текст в Public/Embed.
3. Viewport стенда был ниже iframe, из-за чего Chromium не мог нажать кнопку редактора. Viewport приведён к принятому в основном e2e наборе 1920×1080.
4. Используемый WebKit не передавал Strict cookies между тестовыми хостами `*.sso.test`. Дифференциальный прогон с пустым профилем на `*.sso.example.com` сохранил обе cookies и открыл iframe. Тестовый стенд переведён на согласованные sibling hosts под `example.com`; production cookie policy не менялась.

## Docker и воспроизведение

Из репозитория UI:

```sh
bash tests/sso/run.sh
```

Граница тестирования: браузер и публичные HTTP-эндпоинты настоящих BFF/auth/US; только внешнее приложение заменено тестовым backend. Проверяются автовход; CORS; неверный, отозванный bearer и отсутствие права; outage, некорректный ответ и неожиданный HTTP 202; обычный вход, refresh/logout и независимость сессий; редактирование дашборда; машинные записи и анонимные Public/Embed.

HTML-отчёт локально находится в `tests/artifacts/sso/index.html`. Скрипт успешно удалил контейнеры, временные тома и сеть своего проекта; дополнительный прогон с рабочим verifier также очищен. WebKit в Docker не заменяет проверку настоящего Safari. Проверка HTML refresh принудительно меняет время истечения cookie и не заменяет ожидание фактического истечения access token.
